# Plaster 7: alert eskalacji CRD → dział zakupów — Implementation Plan

> REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Przy auto-blokadzie zamówienia (przekroczenie progu CRD w `update_crd`, plaster 4) powiadomić dział zakupów spółki (RFP §5.2 „przekierowanie do Kupca + alert przy przekroczeniu progu").

**Architecture:** Rozszerzenie endpointu `update_crd` w `app/routers/consolidation.py` o wywołanie `notify(db, purchasing_users(db, po.company_id), kind="crd_escalation", ...)` — TYLKO przy PRZEJŚCIU w `zablokowane` (nie przy ponownym zapisie już zablokowanego). Reużywa istniejącej infrastruktury powiadomień.

**Tech Stack:** FastAPI, SQLAlchemy, pytest.

## Global Constraints
- Alert TYLKO na przejściu: `was_blocked == False` i nowy status `zablokowane`. Bez tego re-zapis spamowałby.
- Reużyj `notify` i `purchasing_users` z `app.notifications` (nie twórz nowego kanału).
- `kind="crd_escalation"` (nowy typ — `notify` działa bez wiersza NotificationRule, kanał domyślnie włączony).
- Nie zmieniaj logiki progu/blokady (plaster 4) — tylko dokładasz powiadomienie po ustaleniu nowego statusu.

    was_blocked = po.cart_status == CartStatus.zablokowane.value
